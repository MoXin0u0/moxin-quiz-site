## 0. 一頁決策與工作邊界
目前不是缺乏功能，而是需要把 V5 已有的 Local-first、PWA、Google Drive 可選同步、備份、題庫工作室及多主題產品能力，轉化為可持續維護的正式產品。工程安全、UI／UX、主題設計、品牌與法律文件不可各自孤立修改。
**決策規則**：先封存可恢復基準，安全與政策清查先行；通用 UX／設計系統可先於「墨境」法務核准作業；**新品牌對外上線必須另有核准 Gate**。任何設計／法律文件修改均不可暗改 V5 資料協定。

### 0.1 不得破壞的 V5 不變條件
- Local-only 不登入仍可執行核心學習；OAuth 只由使用者明確觸發，失敗不阻斷本機操作。
- 本機先寫入，雲端選用；同步、完整備份分開，資料離線可用。
- V5 IndexedDB 為 v4，既有 DB 名稱 `moxin-quiz-v3` 是歷史儲存識別，不可因品牌更名直接取代。
- 帳號 A 未明確確認的待同步資料不得送到 B；裝置撤銷後不得繼續推送。
- 題庫／題目／練習紀錄永久 ID、Schema、雲端 profile、備份格式與歷史資料需兼容。
- 考試原始截止時間、快照與冪等交卷必須保留；恢復不得延長考試。
- 不要同時改 Google Pages 網址、OAuth origin、PWA scope 和顯示品牌；每項均需獨立遷移方案。
- 法律文件不得聲稱程式未做的功能、絕對安全性或實際上無法做到的資料刪除。

## 3. 使用者協議、隱私政策與權益：專項設計判決
### 3.1 現行文件可直接支持的敘述
- `terms.html` 已說明服務性質、本機資料主要保存於瀏覽器、Google Drive appDataFolder 為選用、使用者需自行確認匯入內容的使用權，以及 GitHub Pages/Google 第三方服務。
- `privacy.html` 已列題庫、筆記、紀錄、草稿、設定等本機資料，Google Drive 的 `drive.appdata` 範圍、帳號 permission ID、名稱／email／照片（若有）、access token 僅存在頁面記憶體，以及 unlink 不等於刪除雲端資料。
- 政策頁目前均只有 GitHub Issues 當主要聯絡入口；條款載有「使用即表示理解並同意」概述，但沒有政策版本紀錄、重大變更通知及具體的接受機制設計。
- Google Drive 同步是選用功能；不應將隱私政策或服務條款誤寫成「必須註冊帳號才能使用」。
### 3.2 需要查證，不能在正式政策直接寫死的資訊
- 合法且適當的服務提供者／資料管理者名稱及可公開的聯絡方式；適用司法管轄區與服務目標年齡。
- 是否引入分析工具、Cookie、錯誤回報、回饋表單、寄信服務、用戶群資料或其他第三方；目前沒有足夠證據保證「完全無紀錄／無 Cookie」。
- Google 帳號資訊在本機或雲端的實際保存位置、保存期限、清除方式；含 Drive appDataFolder 內容是否支援 App 內刪除及恢復。
- 使用者自製與匯入題庫是否公開分享、作者題庫授權依據、公開下載之著作權規則，以及有無未來收費規劃。
- 條款是否需要在首次使用或首次同步時有明示同意；接受紀錄是否保存在本機或與雲端同步；不得由工程自行推定其法律必要性。
- 發生資料安全事件時如何通知、處理申請的服務能力與紀錄保留範圍。
### 3.3 使用者資料生命週期的「四動作不可混淆」
| 使用者操作 | 目前程式／文件支持的概念 | 文案必須避免 |
| --- | --- | --- |
| 解除裝置雲端連結 | 保留該裝置的本機資料，解除目前雲端關聯。 | 不可寫「雲端資料已全部刪除」。 |
| 在 Google 帳號撤銷第三方存取 | 撤銷該應用的授權，可能須重新授權才能同步。 | 不可寫「已自動刪掉既存 Drive appData」。 |
| 清除瀏覽器網站資料 | 刪除該瀏覽器 origin 的資料；各裝置另行獨立處理。 | 不可寫「其他裝置／Google 同步資料同步移除」。 |
| 刪除 appDataFolder 內容 | 須先查實目前是否支援、Google 提供何種刪除途徑，以及如何防止後續同步重建。 | 不可在未實作及驗證前提供「一鍵完全刪除」承諾。 |

### 3.4 協議與功能互動設計原則
- 應提供從首頁、頁尾、設定和（適當時機的）雲端啟用流程可到達的 Terms／Privacy；手機和 PWA 也必須可閱讀。
- Google OAuth 授權是與 Google 的授權操作，不等於對網站服務條款全數接受；需分清資訊告知、必要同意與功能開關。
- 不預設要求所有 Local-only 訪客勾選隱私政策。若需明示條款接受，先由法律／產品確認範圍、情境與提供條款審閱的方式。
- 對重大資料用途變動，應有版本、變更摘要、必要時重新通知與同意的決策程序。
- 不能以「使用者自行負責」或「不保證任何事情」等泛用文字，替代法律上不得排除的合理責任。
- 條款與隱私各司其職：權利義務／著作權／服務限制在 Terms；資料流／第三方／保存刪除／個資權利在 Privacy；關鍵操作旁提供簡短白話摘要。
### 3.5 法規與平台政策查核基礎（後續法律審稿清單，不是合規結論）
- 臺灣《個人資料保護法》應檢查第 3、8、11、12、19 等條款是否對實際蒐集／利用活動適用，以及告知、資料權利與事件處置。官方來源：https://law.moj.gov.tw/LawClass/LawAll.aspx?PCode=I0050021
- 臺灣《消費者保護法》對適用的定型化契約要求平等互惠及合理揭露，不可寫顯失公平的免責或單方變更條款。官方來源：https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=J0170001
- Google API Services User Data Policy 規範清楚揭露、必要範圍、Limited Use 及資料用途變更，必須與實際 OAuth scope 及 UI 一致。官方來源：https://developers.google.com/terms/api-services-user-data-policy
- 使用者撤銷 Google 第三方權限可依 Google 官方說明操作，但撤權不等於自動清除所有已存資料。官方來源：https://support.google.com/accounts/answer/14012355
