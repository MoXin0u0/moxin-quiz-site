# B02 D-02｜不建立案件清冊的低維護資料保存方案（候選）

**查核日期：2026-10-21｜狀態：可行性規劃，不代表已安裝或驗收。**

產品負責人 2026-10-13 指示「案件清冊這先跳過」。此決策持續有效：**不新增 Excel、Google Sheets、資料庫或公開 GitHub 案件清冊；不自行存取或刪除真實使用者回覆。**

## 不變規則與風險

- 一般 Google Forms：**結案後 1 年**；備用 Gmail：**結案後 2 年**；皆**每 3 個月人工檢查**；特殊案件各自評估；無自動刪除。
- 每季檢查 ≠ 保存期限可以額外延長 3 個月；應於各筆案件的到期日個別處理。
- Google Forms 原生回覆列表通常只有提交時間與內容，未提供經驗證的穩定「結案日」或「個案保存到期日」欄位；匿名表單也可能沒有電子郵件可追蹤。
- Gmail「標籤」「封存」≠ 實際結案日期或刪除完成；整個信箱其他作品及 Google 安全通知不可受本站保存規則影響。
- **完全不保留案件到期線索，就無法穩定執行以結案日為起點的一年／兩年保存規則。** 不能在沒有追蹤方式時把公開管理期限說成已被保證落實。

## A｜維持暫緩（目前生效的專案決定）

- Forms 和 Gmail 繼續由負責人手動查看、回覆和保護資料。
- 現有 SOP 保留而不開發新工具；保留人工刪除及法定個資請求的義務。
- 發布 Gate 仍 **PENDING**：沒有實際到期追蹤與不誤刪的證據。此狀態不應被描述成已可按每個結案日履約。

## B｜日後如經負責人另外同意，可採「每件結案僅設一個私人到期提醒」，不製作表格

這是**待核准的替代作法**，不是已授權創建提醒，更不是本輪要操作的個人行事曆。

1. **單件結案時才設定**：Forms 到期日＝實際結案日期加 1 年；Gmail＝加 2 年。提醒日直接設在到期日（或事前適當期間），不要把季度盤點當成到期日。
2. **只留最低限度非敏感線索**：例如「墨忻 Forms／一筆到期複核」＋內部不含個資代碼、來源提交時間與必要區分，避免存姓名、電子郵件、詳細說明、私人題庫、身分證件或密碼。提醒本身不包含可讓其他人讀取案件內容的公開連結。
3. **查回原資料再核對**：到期時登入各平台，在 Google Forms 個別回覆／Gmail 執行人工二次辨識；如無法可靠辨識，標記待處理並採非公開方式補查，絕不猜測序號刪除。
4. **依法審查例外**：資安、權利請求、著作權或爭議等，改設個別複核日期並記最低必要理由；不得只因特殊分類就無限期延長。
5. **刪除並驗證**：先確認保存必要性與副本，再人工個別刪除；Forms 單筆刪除不可復原。Gmail 須注意收件、寄件、垃圾桶及另存副本。驗證僅能針對本人可管理的範圍，不宣稱第三方備份全數消失。
6. **另有季度檢查**：每 3 個月查看是否有到期提醒未處理、例外是否需重新審查。提醒本身是私人個案線索，不要求整體清冊，**但若日後數量增多，仍須重新評估管理可靠性**。

## C｜低風險測試與正式啟用門檻

- [ ] 負責人是否接受不建立清冊、改用個別私人到期提醒（未同意前維持 A）。
- [ ] 以虛構代碼演練跨年度結案日、到期日期與季度盤點；勿製作真實案件備份。
- [ ] 以自建、無個資測試回覆驗證 Forms 單筆辨識／刪除流程（刪除前仍需明確授權）。
- [ ] 以自發測試郵件驗證 Gmail 標籤、收／寄信與刪除、垃圾桶管理。
- [ ] 確認資料副本（Forms CSV、Sheets 若有、Gmail 轉寄／備份）及其權限。
- [ ] 評估臺灣個資法第 11 條及第 13 條的保存、刪除與依法准駁時限；不得只依一般管理期限拒絕提前請求。
- [ ] 對外政策精準區分「既定管理基準／預定人工檢查」與「已具體執行完成」，不宣稱自動清除。
