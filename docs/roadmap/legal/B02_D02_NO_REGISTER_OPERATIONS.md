## 一、已批准的作業邊界

| 項目 | 已核准規則 |
| --- | --- |
| Google Forms 一般案件 | **實際結案日起滿 1 個日曆年**時進行到期複核 |
| Gmail 備援一般案件 | **實際結案日起滿 2 個日曆年**時進行到期複核 |
| 季度盤點 | **每 3 個日曆月人工檢查**，不把個案到期日往後延 |
| 到期追蹤方式 | **每一筆已結案的一般案件設定單筆、私人、非敏感的到期提醒** |
| 案件清冊 | Excel／Google Sheets／其他集中案件資料庫仍**暫緩，不建立** |
| 刪除方式 | **人工辨識、依法審查、人工逐筆刪除與核對**；沒有自動刪除 |
| 尚未結案 | 不開始結案後保存倒數；持續正常處理，不得無理由無限積壓 |
| 特殊／提前請求 | 著作權、資安、個資權利、法律爭議依個案保存必要與適用法律判斷，必要時優先處理 |

**本輪核准的是管理方式及虛構測試**，尚未指定使用何種私人提醒平台、預設提醒時間或季度檢查的具體開始日；不應自動選擇個人行事曆或建立真實任務。本次不操作 Google Forms、Gmail 或使用者雲端資料。

## 二、日後執行 SOP（需先以真實平台操作驗收）

1. **接案分流**：正常處理 Forms／Gmail 內容，標示一般或特殊；內容最少化，避免在任何公開工具記錄私人資料。
2. **確認結案**：實際處理完成後記下所採用的當地日曆結案日期；若案件重啟，原到期提醒應人工取消／調整，重新依最終結案日計算。
3. **建立單筆私人到期提醒**：一般 Forms 結案日 +1 日曆年，Gmail +2 日曆年；提醒標題只含「墨忻／Forms 或 Gmail／到期複核」及最低限度、不含個資的內部代碼。**提醒到期 ≠ 系統自動刪除**。實作時須確認私人存取權與通知是否確實可達。
4. **留足以辨識的最少必要線索**：可在私密提醒中記「來源回覆提交日期／時間、非敏感分類、代碼」，不得存整份訊息、聯絡 Email、身分資料、密碼、Token、附件或私人題庫；不把原件可存取的管理 URL 公開。提交時間可能仍不足以唯一定位，遇到重複必須中止刪除。
5. **季度複查**：每隔三個日曆月核對逾期未處理提醒、即將到期項目與特殊案件；季度日期晚於某筆到期日，仍須依該筆到期日行事，**不得等季度盤點才統一刪除**。
6. **個案到期人工核對**：到期時先回到原始平台確認至少兩項可辨識線索、沒有其他相同回覆、沒有法律保留原因或尚未結案的往來；避免只憑列表序位、粗略時間或代碼猜測。
7. **刪除與復核**：只刪經查明不需留存的正確個案及本人可控制的副本；Forms 個別回覆刪除不可復原。Gmail 需留意收件、寄件、往返、附件及垃圾桶。若辨識有歧義、權利請求未結或存在保留事由，**不得刪除**，改由非公開管道補查並設定具體複核時間。
8. **完成後**：確認原平台內目標已不再可見，保留最低必要的完成／例外紀錄，移除不再必要的私人提醒；不得宣稱 Google 自行保存的所有備份已同步永久刪除。

## 三、純虛構日期演練

以下案例純為 CI 與流程推演，**不對應真實表單、信件或私人行事曆**：

| 測試代碼 | 管道 | 虛構結案日 | 推演到期日 | 驗證目的 |
| --- | --- | --- | --- | --- |
| SIM-F01 | Forms | 2026-10-21 | 2027-10-21 | 一般滿 1 日曆年 |
| SIM-G01 | Gmail | 2026-10-21 | 2028-10-21 | 一般滿 2 日曆年 |
| SIM-F02 | Forms | 2026-12-31 | 2027-12-31 | 跨年度 |
| SIM-G02 | Gmail | 2026-12-31 | 2028-12-31 | 跨年度兩年 |
| SIM-F03 | Forms | 2024-02-29 | 2025-02-28 | 閏日無同月同日時採保守月底推演 |
| SIM-G03 | Gmail | 2024-02-29 | 2026-02-28 | 同上，兩年 |
| SIM-F04 | Forms | 2027-03-01 | 2028-03-01 | 閏年年份但有效的週年日 |

**邊界規則**：測試使用民用日曆日（`YYYY-MM-DD`）加整數日曆年，不用 365／730 天、UTC 時差毫秒或固定 90 天。當目標年的 2 月沒有 29 日，*演練*先採 2 月 28 日這個較早的保守日期供人工複核；正式計算與適用法定期間的法律效果仍須再確認，這不是自動確定合法刪除日。

**季度例**：2027-01-21 的 3 個月後是 2027-04-21，但某 Forms 案件若在 2027-03-01 到期，不能延至 4 月的例行稽核。

**安全負向案例**：尚未結案、特殊案件、日期無效（如 2026-02-29）、有法律保留原因、提交資訊不足以唯一辨識、尚未達期限，皆不得形成一般自動刪除操作。

測試來源：`tests/b02-retention-calendar-run.mjs`，已接入 `npm test`／CI。檢查結果需以**最新 PR Head GitHub Actions**為準；此測試只模擬預期規則，不驗證提醒平台通知可靠性或 Google 真實刪除行為。
