# B02｜Google Forms 回覆結案、保存與人工刪除 SOP（草案）

> D-02／LEG-012／LEG-018／LEG-020；決策補充：2026-10-13。
> **狀態**：產品負責人同意 Google Forms **一般案件結案後保留 1 年、每 3 個月人工檢查到期案件**。此為管理政策決議；人工清冊、實際刪除測試、個資／法律審查與正式發布**尚未完成**。沒有自動刪除。不要將草案描述為已實施的回覆清理系統。

## 一、適用與排除

- 僅適用墨忻刷題網以 Google Forms 收到的一般意見、功能錯誤、使用建議、題庫勘誤等普通回報。實際**結案日**作為一般案件一年的起算日，不以提交日或首次回覆日計算。未結案案件不開始結案後倒數；也不表示可以毫無理由永久不處理。
- **檢查週期為每 3 個月人工檢查**。應同時盤點下一個季度內將到期的案件，提前安排**到期日人工刪除提醒**；季度稽核是對執行情況的核對，**不是將結案後一年的保存期限自動延長三個月**。過期或依法要求提前處理的案件須儘速個別處理，不必等待下次季度檢查。
- 涉及個人資料權利、著作權／授權爭議、資安事故與法律爭議者**依個案處理必要、法律依據與證據保存需求**決定例外；應記錄例外理由與下次重新評估日期，不承諾一律保留一年或可無限期延長，亦不得忽略依法提前刪除的請求。
- **不適用**備用 Gmail（一般案件結案後 2 年／每 3 個月人工檢查，見 [Gmail SOP](./B02_GMAIL_RETENTION_SOP.md)）、使用者瀏覽器本機內容、Google Drive `appDataFolder` 同步檔案及其他作品的資料。
- 目前負責人回報**沒有連結 Google Sheets**；仍需正式驗證表單後台，並檢查是否存在人工下載 CSV、備份、截圖、轉寄或其他衍生副本。日後若連結 Sheets，表單刪除、試算表刪除與解除連結不能互相視為已清理所有資料。
- 2026-10-13 負責人確認舊檔案上傳題所建立的 Drive 資料夾**檢查時為空**。這不是全部歷史副本不存在或永久刪除的證明。目前「發生頁面」已改簡答選填，不再要求上傳附件。

## 二、最小化人工案件清冊（規格，尚未建立）

原則：可存放在**僅負責人能存取、具適當裝置保護的非公開位置**，不得提交至公開 GitHub、任何公開 Issue，亦不要求另建立連結的 Google Sheets。避免為追蹤而複製整份表單回覆、Email 地址、身分文件或私人題庫內容。

| 欄位 | 用途／約束 |
|---|---|
| 案件代碼 | 由負責人自行編排，例如 `F-20261013-001`；不是 Google Forms 保證提供的永久回覆 ID |
| 辨識線索 | 僅保存能人工定位單筆回覆的最低限度資訊，如提交時間與非敏感分類；同時間多件時必須再次核對，**不可僅依序號或列表位置判定** |
| 類別與狀態 | 一般待處理／處理中／已結案／特殊案件暫緩清理 |
| 結案日 | 處理實際完成且已確認無待辦的日期 |
| 一般到期日 | 結案日加 1 年；依實際日曆日期計算，不能直接以回覆提交日替代 |
| 下次提醒／檢查日 | 季度盤點與個別到期提醒可分開記錄 |
| 例外原因及複核日 | 必要時記錄摘要，不包含敏感全文 |
| 清理結果 | 已刪除／待刪除／例外延後／無法識別；記錄執行日及必要的非敏感核對結果 |

**禁止事項**：用表單填答者姓名或 Email 當公開案件編號；在 GitHub 傳送回覆全文或附件；把清冊當成新的永久保存資料庫。到期後清冊也應依最小必要性清理／去識別化。

## 三、人工工作流程（尚待測試）

1. **接收與分類**：在擁有者的 Google Forms「回覆」介面查看單筆回覆；判斷是否為一般或特殊案件，先檢查是否包含使用者無意提交的敏感資料。必要時優先限制存取及處理，勿散布內容。
2. **案件與結案紀錄**：以最小化清冊建立案件代碼、辨識線索及狀態；處理完成才設定結案日及一年到期日。匿名回覆沒有可追蹤的寄件人時，不能保證能個別通知結果。
3. **每 3 個月人工盤點**：確認已到期、即將於下一季到期及特殊例外案件；為即將到期者設定個別日期提醒，以避免季度盤點造成期限超過一年。盤點時審查回覆、下載 CSV／試算表／副本是否實際存在；如有，另外管理。
4. **逐筆核對**：按清冊辨識線索找到原回覆，檢查提交時間、分類、主旨等資訊足以確認目標；如存在同名或相同時間的多筆紀錄，先暫緩刪除、重新辨識，防止誤刪。
5. **單筆刪除**：Google Forms 編輯介面 →「回覆」→「個別」→以「上一個／下一個」找正確回覆 → 按該筆「刪除」並確認。**不要使用「摘要 → 刪除所有回覆」來執行單筆清理**。Google 說明：表單回覆刪除後無法復原，需先確認沒有法定必要保留的內容。
6. **完成驗證與清冊更新**：再次在 Forms「個別」查核目標不再出現，記錄日期與成功／失敗；如原本另有 CSV、試算表或附件等由本人管理的副本，應個別評估並依流程處理。不得聲稱能刪除 Google 不可直接存取的系統副本或使用者自行保有的副本。
7. **提前／特殊請求**：使用者依法請求查閱、更正、停止利用或刪除時，改由私密管道處理必要的身分／案件辨識，不要求在公開 GitHub Issue 提交憑證、身分證件或私人資料。避免為確認身分收集超過必要的資料。
8. **低風險驗收**：只選擇**明確標記、無個資的測試回覆**驗證「個別刪除」，先記下表單回覆總數與目標的非敏感辨識資訊，執行後檢查目標消失、其他測試回覆仍存在；**沒有負責人事先同意，不刪任何真實使用者回覆**。

## 四、官方依據與已知限制

- [Google 官方｜選擇表單回覆的儲存位置、刪除個別回覆](https://support.google.com/docs/answer/2917686?hl=zh-Hant)：Google Forms 支援「回覆 → 個別 → 刪除」，刪除後無法復原；若連結 Google Sheets，該試算表是另外的雲端檔案。
- [Google 官方｜查看與管理表單回覆](https://support.google.com/docs/answer/139706?hl=zh-Hant)：Forms 可檢視個別回覆，亦可下載 CSV；**匯出並不等於只保存一份資料**。
- 這是人工管理 SOP，沒有證據顯示 Forms 內建結案狀態、逐筆一年保存自動清理或具有穩定可供人工引用的「回覆 ID」欄位。若正式使用中無法可靠識別個別回覆，必須修訂清冊／流程，不可冒險刪除。

## 六、2026-10-13 單筆回覆介面檢查（階段回報）

產品負責人在收到「開啟 Google Forms **回覆 → 個別**、找到之前的無敏感資料測試回覆、查看單筆內容與刪除圖示，**不要按刪除**」的操作指引後，回覆**「完成」**。記錄為 **「個別回覆介面查看：負責人已回報完成」**；沒有本次畫面截圖或逐項細節，因此**尚未獨立驗證具體刪除圖示、唯一辨識正確性或實際刪除結果**。不將本回報寫成「單筆刪除 PASS」，也未刪除任何回覆。下一步應先決定**非公開的最小化案件清冊儲存方式**、用無個資的測試紀錄驗證案件代碼／提交時間／結案日／到期日，再由負責人明確授權才測試單筆刪除；不要在公開 GitHub 儲存個案內容。
