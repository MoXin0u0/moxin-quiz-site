# B02 D-09｜使用者協議接受模式與資料同意邊界：決策候選

**盤點日期：2026-10-21｜追蹤 LEG-006／008／009／015／017／020。**
**狀態：候選設計，負責人尚未選定 D-09 方案；非正式法律意見，亦未修改正式站或使用者資料。**

## 1. 已有事實與不可違反的產品條件

1. 墨忻刷題網是 **Local-first 的靜態網站**，本機核心學習功能不需要 Google 登入。Google Drive `drive.appdata` 跨裝置同步為使用者主動選用的功能。
2. 目前正式 `main` 政策為 2026-10-08 內容；B02 分支的 B02-1.0（候選稿最後更新 2026-10-20）主要補述既有實際同步資料、Google Forms/Gmail 聯絡、保存與權利資訊。本輪未核實新增的 scope、付費、註冊系統或自建資料庫。
3. **Google OAuth 對 API 存取的授權不等於使用者接受本網站全部服務條款**；閱讀政策或繼續瀏覽也不得虛構為已明示接受。
4. 現有網站沒有可可信地紀錄全部匿名、離線及跨裝置使用者接受證據的登入伺服器；本機旗標頂多是裝置上的使用者介面偏好，不能當成可跨裝置核驗的法律契約簽署證明。
5. 全年齡適用包含未成年人；必要法定代理人同意或 Google 受監護帳號限制，須獨立審核，不可由一個通用勾選框自動解決。
6. 是否依法需要明示同意取決於**蒐集及利用的法律依據與具體行為**；不應誤稱所有政策文字修正必須取得重新同意，或只要無條款勾選就一定足以合法進行新增資料用途。

## 2. 建議方案比較（待負責人確認）

| 方案 | 使用者操作 | 好處 | 代價及風險 | 適用判斷 |
| --- | --- | --- | --- | --- |
| **D09-A（建議）情境化告知、必要時獨立明示同意** | 本機學習可以直接進入；首頁／設定顯著連到 Terms／Privacy 和更新摘要；啟用 Google 同步前再次顯示資料用途及權限。在法律或 Google 政策要求新增同意的**新用途**，先明確告知並以可證實的使用者操作取得同意，未同意就不啟用該新用途。 | 保留本機可用性、不把 OAuth 當服務條款接受、不額外收集匿名學習者身分資訊；可分離一般資訊告知與真實法律同意 | 在需要具有拘束力條款的情境仍須專案法律評估；僅顯示連結不是所有目的變更之充分同意 | 優先候選；B02 現有「揭露補全」更新可先規劃公告，但合法性仍待審 |
| D09-B：強制所有使用者進站勾選 | 每次新版本前需勾選，才能使用任何功能 | 有可見的同意操作 | 阻礙本機／離線使用；匿名本機旗標缺乏可稽核身分綁定；未成年人及不同裝置同意證明困難；可能造成沒有必要的同意疲勞 | 不建議對本機學習套用 |
| D09-C：僅對「啟用雲端」提供獨立協議接受 | 本機可直接用，按雲端連結時有站內額外確認，然後再由 Google OAuth 授權 | 當雲端涉及另外的契約或必須同意之用途時，操作範圍清楚 | 會增加流程和版本／狀態紀錄；若沒有真實同意需求，可能造成不必要摩擦，且不能靠此迴避 Google OAuth 同意 | 作為某些重大變更的後續擴充，不預設 B02 必須強制 |

## 3. D-08 到 D-09 的通知／授權分流（建議）

| 變更情境 | 當前建議 | 不得宣稱 |
| --- | --- | --- |
| 更新既有功能的文字、修正資訊、補足目前 13 種同步資料告知（不改實際資料用途） | 正式上線時公告版本、真實公告日／生效日及可讀摘要；在首頁、設定及同步入口提供可找到的 Terms／Privacy 連結 | 不能用新版頁面的候選「最後更新」日期冒充已正式上線 |
| 新增 Google API scope、Google 資料新用途、新第三方接收者或超出先前揭露目的 | **先停止新用途**，完成法律與 Google User Data Policy 查核，必要時取得新增知情同意與 OAuth 重新授權，再啟用 | OAuth 舊授權不等於新目的或站內條款已同意 |
| 未來若開通付費服務、強制帳號或重大變更使用者責任／權利 | 另開專案核准與通知／接受方式；不得預設對既有使用者默認生效 | 不能以使用既有免費功能視為自動購買或接受新付費條款 |
| 修正安全事件及資料權利處理方式 | 以適用法律與實際通知能力評估告知時點、範圍與證據，必要時另行個別通知 | 不能保證本站可以主動聯絡到全部匿名或離線使用者 |

## 4. D09-A 若通過的工程驗收契約（尚不代表通過）

- 首頁／學習大廳／設定至少提供清楚可達的條款／隱私入口和簡要更新訊息；手機端、鍵盤、深淺模式可讀。
- 第一次主動連結 Google 前，在授權操作附近提示 scope、同步資料類別、Privacy/Terms，以及「OAuth ≠ 網站協議接受」的差異。
- 不對本機離線練習跳出強制阻斷式接受視窗；不依賴 Google 登入才能閱讀政策。
- 不能用 `localStorage` 保存一個「真實身份已同意」的法律證據宣稱。若未來因具體目的需要保留接受證據，另行設計最少化、可稽核的操作／版本紀錄及刪除政策。
- 若沒有法規要求的同意事件，就只作明確告知，不用「點擊繼續即同意一切」取代明示同意。
- 發布仍受 D-01 個資蒐集者告知、D-02 實際保存操作、D-05 第三方題庫權利、D-08 正式生效／通知和 D-10 法律最後審核之獨立 Gate 限制。

## 5. 依據與待審

- [臺灣《個人資料保護法》第 7／8／19／20 條](https://law.moj.gov.tw/LawClass/LawAll.aspx?PCode=I0050021)：同意與告知的法定條件、特定目的外使用等；須核對各條當時有效施行版本，並由具資格人士評估本案適用。
- [Google API Services User Data Policy](https://developers.google.com/terms/api-services-user-data-policy)：Google 使用者資料必須明確揭露實際用途；若將存取或使用方式擴大為先前未揭露的新目的，須事前告知並依政策取得同意，不得用舊 OAuth 授權概括代替。
- [Google OAuth 2.0 Policies](https://developers.google.com/identity/protocols/oauth2/policies)：應用品牌與 OAuth 範圍需與實際資料存取、Google 授權介面一致。
