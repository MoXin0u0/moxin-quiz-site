## 追蹤結構

- 所有問題保留原編號。新工程問題從 AUD-033 起，不重新排序 UI/BR/LEG。
- 一般 Issue / PR 優先用簡短摘要記錄範圍、測試、未解風險和回滾；只有個資、內容權利或重大資料變更等真正高風險事項才展開詳細證據矩陣。
- 交叉工作可合併執行，但每個來源 ID 單獨驗收，不以單一完成勾選掩蓋差異。
- 工程與 UI 狀態必須區分：「來源文件風險」「程式碼已確認」「已實機重現」「已修改但待測」「驗收通過」。
- B02 的法律項目另區分「法律與平台要求待確認」「資料流已核實」「文字草案」「法律與產品核准」「已發布」。
- 發現 V5 原有功能或資料安全不變條件失效時，暫停合併並提供回滾與影響分析。
