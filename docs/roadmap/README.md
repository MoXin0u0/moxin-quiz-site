## 追蹤結構

- 所有問題保留原編號。新工程問題從 AUD-033 起，不重新排序 UI/BR/LEG。
- Issue / PR 最少記錄：來源 ID、證據性質、使用者影響、風險、驗收矩陣、原始 commit、測試結果、回滾、負責人、核准。
- 交叉工作可合併執行，但每個來源 ID 單獨驗收，不以單一完成勾選掩蓋差異。
- 工程與 UI 狀態必須區分：「來源文件風險」「程式碼已確認」「已實機重現」「已修改但待測」「驗收通過」。
- B02 的法律項目另區分「法律與平台要求待確認」「資料流已核實」「文字草案」「法律與產品核准」「已發布」。
- 發現 V5 原有功能或資料安全不變條件失效時，暫停合併並提供回滾與影響分析。

## 測試與發布責任

- 原則上先跑 `npm run ci` 和相關專項測試，並依風險補上瀏覽器／異機證據。
- B01 會修復 `main` 的 Browser CI 覆蓋與 `app.html` paths；**B00 不把既有的 CI 缺口寫成已修好**。
- 無障礙、效能、商標合法性、Google 政策、資料刪除路徑不可因純文字 PR 或其他測試綠燈就宣稱通過。
- 上線、切換網域、OAuth、DB 遷移、正式品牌採用是不同的決策，不與一般畫面整理一同進行。
