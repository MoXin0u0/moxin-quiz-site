# 墨忻刷題網 v4.0 — UX Density / Information Architecture Audit

## 原則

功能增加後，不再採用「同一頁一路向下堆卡片」作為預設策略。

1. 今天要看什麼，與設定怎麼改分開。
2. 高頻操作放總覽；低頻設定進次層。
3. 一頁同時存在三種以上不同任務時，優先建立第二層導覽。
4. 手機版避免必須滑過多個大型 Dashboard 才到主要操作。
5. 功能資料範圍必須明確可見，不以「全部資料」作為危險的隱含預設。

## 今日學習 — 本次已修

原「今日複習」已同時包含 Review、P3 學習目標、P4 考前衝刺，因此改名為「今日學習」，並建立：

```text
總覽 / 複習 / 學習目標 / 考前衝刺
```

總覽只保留今日決策資訊；完整設定分到各自頁籤。

## P4 題庫範圍 — 本次已修

P4 不再共用 P3 scope，也不再使用「全部題庫」作為自然範圍。

每場考試獨立保存：

- examLabel
- examDate
- sprintEnabled
- sprintBankIds[]
- sprintDailyTarget

至少選一個題庫；可以多選，但未選取題庫完全不參與 P4 統計與安排。

## P3 學習目標 — 本次調整

風險：使用者可能忽略「目標範圍」下拉選單，而誤以為永遠套用全部題庫。

處理：

- 單一題庫選項移到前面。
- 「全部題庫」放到獨立群組並明確標成整體範圍。
- 沒有既有設定時，預設優先使用第一個本機題庫，不自動使用 Global。
- Global 仍保留，因「整體每日學習量」本身是合理需求。

## 我的題庫

目前作者題庫 / 自行新增已有第一層 Tab，但「自行新增」中同時包含匯入工具與題庫清單。

密度：**中**。

後續建議：

```text
作者題庫 / 我的題庫 / 匯入題庫
```

不在 P4.2 同時改，避免一次重構過多主要流程。

## 學習統計

目前功能量尚可，但 P5 將新增 7/30 日趨勢、題型、章節、弱點等。

未來密度：**高**。

P5 開始時應先採用：

```text
總覽 / 趨勢 / 弱點分析 / 題庫分析
```

禁止把所有圖表連續向下堆在同一頁。

## 題庫工作室

目前同時包含工作室、AI Schema、匯出分享與相關工具。

密度：**中高**。

待工作室功能再增加時應拆成：

```text
工作室 / 建題工具 / 匯入匯出
```

目前先不動，避免打斷已穩定的 P1/P2。

## 設定

Desktop 尚可；手機長頁風險較高。

後續建議用 Accordion：

```text
外觀
資料與備份
工作室
離線 / PWA
進階檢查
```

## 模擬考

目前任務單純：選題庫 → 設定題數時間 → 開始。

密度：**低**，暫不拆。

## 作答頁

一次只處理一題，資訊焦點清楚。

密度：**低**。後續也不要把統計、目標設定等管理功能塞進作答頁。
